# Changelog

## 0.1.0-beta — preparation in progress

- Added a native Codex repository marketplace and complete versioned plugin bundle. Namespaced the eight skills with cwk names and retained upstream source mapping and MIT notices.
- Added deterministic archive packaging and isolated native install, discovery, update and uninstall verification, including Superpowers v6.3.0 coexistence.
- Separated skills-only installation from explicitly adopted project rule profiles in documentation and routing inputs.
- Added real model selection and public task evaluation tools with original sanitized observations. Initial selection failures are retained; follow-up changes target demonstrated overactivation without weakening case expectations.
- Hardened opt-in evaluation evidence handling for JSON-escaped secrets and recorded content identity before task execution. These changes affect the evaluation tools, not installed skills.
- Fixed independently reproduced evaluation-tool gaps: indented/literal provider URLs now redact correctly, supervisor checks use a separate credential-free environment, and model timeouts retain partial failure evidence. Replayed stored task artifacts through the corrected checks.
- Added fast CI, issue/PR templates, first-use examples, troubleshooting, compatibility limits and versioned release instructions, including prepared beta release notes and archive checksum verification.
- Reviewed v6.3.0 upstream changes while retaining the v6.2.0 source lineage. No speed, cost or cross-model superiority is claimed.

Installation and removal use the commands in INSTALL.md. Required runtime tooling is a compatible Codex CLI; local checks use Python 3.9+ standard library. Project rules remain separately owned. Rollback uses a previously verified tag/archive; no automatic global rule overwrite occurs.

Hosted publication, maintainer authorization and independent review evidence are tracked in .doc/specs/public-core/tasks.md.
