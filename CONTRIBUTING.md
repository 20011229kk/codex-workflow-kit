# Contributing

Prefer a focused change with a concrete user scenario. Preserve project conventions, authorization boundaries and the eight-skill bundle contract. Keep documentation, requests and fixtures in English.

For a skill change, review positive and negative selection cases, references and existing-user behavior. Keep independent cwk names and original source mapping. Reuse still-valid evidence; rerun affected selection or task observations when their inputs change. Do not relax expectations to improve a score.

For tool changes, add executable contract checks that can expose the defect or missing behavior. Run README's fast commands. CI never uses model credentials. Native installation checks use temporary HOME/CODEX_HOME; actual model runs are explicit and may incur provider costs.

Keep PUBLICATION_MANIFEST.json current only after reviewing the actual file set. Original input hashes in docs/source-files.json do not change merely because delivered files change. Preserve upstream MIT notices in both source and runtime distribution.

Use the PR template to describe behavior, evidence, limits, compatibility and licensing. Do not contribute private business data or material you lack rights to distribute. Release actions follow the maintainer's authorization and the release procedure.
